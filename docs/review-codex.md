# Codex 复盘结论

评审范围：`docs/review-brief.md`、`desktop/plugin.js`、`dashboard/plugin_api.py`、`tests/test_plugin_api.py`。以下按用户字面口径判断：本周期 Token 必须是模型/厂商官方重置窗口内的本地已用 Token，不能用自然周替代。

## Bug 清单

### P0

未发现稳定复现的崩溃、数据破坏或完全阻断页面的问题。

### P1

#### 1. 周用量旁边的“本周期”仍可能切成 5 小时窗

- 现象：多窗口厂商按“剩余百分比最小”选窗口（前端 `desktop/plugin.js:218-226`；后端 `dashboard/plugin_api.py:294-318`）。5 小时窗更紧时，底栏百分比、重置时间和周期 Token 会一起切到 5 小时窗，不再是用户指定的周用量口径。最新代码已能根据 `Weekly/周` 标签避免“周窗临近重置被判成 5h”，但它修复的是窗口长度推断，不是窗口选择。
- 根因：用额度紧张程度代替用户指定的周窗口类型；前后端各自重复同一选择启发式。
- 最小修法：按官方窗口标识/标签明确选择周窗口（Grok 唯一周窗、Codex Weekly、Claude Current week/模型周窗），由后端返回唯一的 `display_window/cycle`，前端直接消费，删除两套“最紧窗口”选择逻辑。

#### 2. 没有官方窗口的模型仍被放进“本周期 Token”，实际数据是自然周

- 现象：`aggregate_reset_cycles()` 找不到 provider 官方窗口时，使用 `fallback_start` 并写入 `kind="calendar_week"`、`label="自然周"`（`dashboard/plugin_api.py:405-417`）。这些行进入 `usage.cycle_by_model`（`dashboard/plugin_api.py:994-995`），而主表已直接消费该字段并宣称“官方重置窗内已用”（`desktop/plugin.js:773-833`）。因此无官方窗口的模型会以自然周数冒充本周期。
- 根因：为了让所有模型都有数，引入了与需求冲突的自然周 fallback。
- 最小修法：无可确认官方窗口的 provider 不参与 cycle 聚合，返回“周期不可得/原因”；自然周只保留在现有自然周期统计中。删除 `calendar_week` 分支，不留兼容层。

#### 3. 跨重置点的长会话无法按官方窗口准确拆分，界面却按精确值展示

- 现象：cycle SQL 只取会话累计量，并以 `sessions.started_at` 判断整条记录是否落入窗口（`dashboard/plugin_api.py:353-383`、`414-430`）。会话在重置前开始、重置后继续产生的 Token 会全部被排除；窗口内开始但跨出窗口的累计量也无法拆分。
- 根因：持久层只有会话/模型累计值，没有带发生时间的 Token 增量；自然周期聚合里声明的 `session_started_at` 限制没有随 cycle 数据暴露给前端。
- 最小修法：正确方案是按 API 调用或可增量采样的时间点持久化 Token，再按窗口边界求和。完成前至少把 cycle 标为“按会话开始时间近似”，不能继续显示成无条件精确的“官方窗内已用”。

### P2

#### 4. 模型多选无法表达“一个都不显示”

- 现象：`modelAllowed()` 把 `models=[]` 解释成全部显示（`desktop/plugin.js:74-77`）；取消最后一个模型后保存空数组，主表反而恢复全部。“全部”取消勾选时还写入完整模型列表（`desktop/plugin.js:838-889`），视觉动作与结果相反。
- 根因：`null` 和空数组都被当成“全部”，全选 checkbox 的状态机不完整。
- 最小修法：只让 `null` 表示全部，`[]` 表示全不选；提供明确的“全选 / 清空”动作，并测试取消最后一项后的空状态。

#### 5. 过期额度在底栏没有可见标记，用户会把旧百分比和旧重置时间当成实时值

- 现象：Grok 缓存过期时后端保留旧数并标为 `stale`，主页面额度卡会显示“过期”；但 `quotaSnapshot()` 对 `stale` 与 `available` 同样处理，`StatusQuotaChip` 只显示百分比、周期数和倒计时（`desktop/plugin.js:238-266`、`1126-1169`）。底栏最常看的位置没有陈旧提示。
- 根因：状态字段没有进入底栏快照和渲染状态。
- 最小修法：把 provider status 放进 snapshot；`stale` 在厂商名旁显示短标记或弱化样式，悬浮中显示采样时间，不能只在模型用量页提示。

## 界面与操作逻辑优化（最多 6 条）

1. 底栏每家固定顺序为“厂商 → 周用量百分比 → 本周期 Token → 距重置”，四项作为一个整体显示/隐藏；窗口类型由后端明确给出，不允许 5 小时窗和周窗按剩余百分比抢占。
2. 当前主表四列方向正确，但“窗口”应显示官方原始含义（如“本周”“本周 Opus”），不要只显示由剩余时间猜出的“官方周窗/5小时窗”；重置列保留倒计时，完整时间放悬浮。
3. 模型设置改成固定高度的可滚动多选区，顶部放“全选 / 清空”和“已选 n/N”；模型多时不再让整排 checkbox 无限增高。
4. 状态条内容、模型、单位三组已经分行；再给每组增加简短标题或边界，并把厂商三项与“今日/自然周”分开，避免把汇总项和额度项理解成同一层级。
5. 数值状态统一：有效零值显示 `0`，未知显示 `—`，过期显示“过期”；悬浮层同时给出官方窗口、采样时间、不可得原因。
6. Provider 悬浮层先显示本周期与官方额度窗口；今日/自然周/本月属于补充信息，默认折叠，避免与页面顶部自然周期卡重复抢占空间。

## 明确应删除的内容

- 从 cycle API 删除 `calendar_week`/`自然周` fallback；无官方窗口就明确不可得。
- 删除旧的 `colToday/colWeek/colMonth` 存储残留和读取路径，不保留旧键兼容；本周期表不再恢复今日/本周/本月三列。
- 删除当前已无调用的 `CycleHoverCard`，以及 `UsageStatus()` 中只声明不使用的 `modelPeriods`、`cycleMap`、`runtimeModel`（约 `desktop/plugin.js:1301-1334`、`1545-1548`）。
- Provider 悬浮层中的今日/本周/本月三张 `PeriodMini` 若不做折叠，应直接删除；同类自然周期信息已在页面顶部和可选底栏汇总出现。
- 删除 `cycleKindLabel()` 对 `calendar_week` 的显示分支；错误口径不应通过 UI 标签继续合法化。

## 验证与测试缺口

- `node --check desktop/plugin.js` 通过。
- `python -m unittest discover -s tests -p test_plugin_api.py`：16 个测试通过。
- 新增测试已覆盖“周标签临近重置仍为 7 天”和“显式第三方 provider 保持原值”。仍未覆盖前端设置与周期表、多个官方窗口必须固定选择周窗、无官方窗口不得回退自然周、跨窗口长会话。测试全绿不能证明本任务口径已完成。
